## Architecture (chosen on evidence, one implementation)
React Native/Expo app + local Expo module `modules/yue-engine` (Kotlin). The module bundles the prebuilt CPU engine from the Killa YuE 1.8.1 release
(`libyueserver_portable.so`, `libkyggml*.so`, 7 `libkycpu-*.so`, the engine's own libc++ as `libyuecxx.so`), runs it as a child process, and talks to its documented
HTTP API on 127.0.0.1:8087 (`POST /synth`, `GET /job`). Needed fixes found on device: (1) engine needs its own libc++ (NDK r30) ahead of React Native's on `LD_LIBRARY_PATH`;
(2) libs must be extracted (`expo.useLegacyPackaging=true`, config plugin `plugins/withLegacyPackaging.js`); (3) models must live in the app's private storage (a file pushed by adb is unreadable by the app).
Config used: supplied ABC score (name slot split by syllable estimate, port of experiment config C2, golden-tested against the Python reference), fixed seeds, 4 render steps, Pop style tags.

## Measured on the Nothing A001 (CPU, Q5, unthrottled; Killa's "gentle" throttling is NOT used)
Sam, 12.1 s of audio, 4 steps, manual engine run: 175 s and 211 s total. Breakdown (engine log): load LM 3.7 s; prefill 9-10 s; melody tokens 44.8 s (147 ms/token);
load NAR 1.5 s; **NAR render 108-138 s (27-35 s per step)**; VAE decode 14.5-20.6 s; MP3 0.7 s.
In the app: Sam 2:59 (12 s song), Emma 2:53 (11 s song). Same seeds + same request give byte-identical output size (193,920 B).
Step test (same tokens re-rendered, Sam): 2 steps 106 s, 3 steps 135 s, 4 steps (full) 181 s, 6 steps 240 s (render-only, AR cached). Rule of thumb: +27 s per step on top of ~70 s fixed + ~55 s AR.
Resources (sampled every 10 s over the whole session, approximate): engine resident 0.5-2.5 GB (includes memory-mapped model pages), CPU avg ~380% (max 456%), battery-sensor temperature 34-40 °C,
MemAvailable minimum 1.35 GB, battery 73% to 70% on USB over the two app runs. Model files: 2.62 GB + 0.53 GB. APK: 48.5 MB. Free storage on phone is now ~6 GB.
Not measured: peak RSS via VmHWM, battery drain on battery power, backgrounded generation.

## Known limitations (honest)
- **Pronunciation is not solved.** The model gets the name only as spelled text. Earlier screening (12 outputs, `research-killa-yue/listening/`) was inconclusive; automatic respelling made things worse. Expect misses (e.g. Emma heard as "Anna" by the recogniser).
- Generation takes about 3 minutes for a 12 s song; the app must stay open (no foreground service, no battery-optimisation exemption, backgrounding untested).
- Models are not downloadable in-app yet: they must be copied into the app's private folder (`files/models/`). Today this was done with `adb` + `run-as`.
- Only Pop was exercised on device; Acoustic and Dance use unvalidated style tags.
- Song is ~12 s (the fixed 3-line verse), not a full-length song.
- Share sheet shows the file under its MediaStore id; the Music file has a proper name.
- The Killa Gold look is re-created (colours, script type, gold rings, turning record, staff animation). No Killa artwork or fonts were copied.
- Other Killa features (Discover, HAMMER, Studio, themes) were never imported, so nothing needed removing. The old voice assistant remains reachable from home.
- Nothing is committed to git (repo has one commit and a large untracked tree).
