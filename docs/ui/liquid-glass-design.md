## 2. Reference video (624.mp4, 12 s, 1440x1920) - what it shows

It is a dark "wallet" app by another product. Only the interaction is used, with none of its branding or content.

- **Orb carousel:** a vertical arc of gradient glass spheres (each month is one orb) with ticks and small labels. Scrolling rotates the arc; the centred orb grows (about 2x) and its detail text appears beside it. Non-selected orbs are small, dim and slightly blurred, and some are plain white or grey discs.
- **Palette identities:** every orb is its own multi-colour gradient (violet/blue, mint/green, coral/orange, teal/cyan, magenta/violet).
- **Glass panel:** swiping up raises a rounded glass sheet from the bottom, tinted in the *selected orb's* palette. The background orbs go soft and blurry behind it, the panel has a grabber, a lit coloured edge and a faint iridescent rim, and its text stays crisp.
- **Mapping to NameSinger:** the arc carousel is the orb theme selector, and the tinted sheet is the glass sheet (settings and theme). The orb palette is chosen by scrolling the arc, and the sheet takes its tint from the selection.

## 3. AndroidLiquidGlass (Kyant0/AndroidLiquidGlass, now "Backdrop")

- License **Apache-2.0**, so it can be used and redistributed.
- Maven Central artifact `io.github.kyant0:backdrop` (2.0.1). It is **Kotlin / Compose Multiplatform**, not an npm package. It ships no high-level components; it draws a *copy of a Compose backdrop layer* into a foreground with blur, refraction and other effects.
- Only the Compose side is documented. I did not find the minimum Android version in the docs I read; the refraction relies on AGSL runtime shaders, which need Android 13 (API 33). I will confirm in the source before building.

### Blocker: the backdrop must be Compose content

The library records a Compose layer (`layerBackdrop`) and re-draws it behind a glass shape. React Native views are **not** Compose layers, so a native glass view sitting over RN content has nothing it can sample. Three ways forward:

| Option | How | Cost | Honest result |
|---|---|---|---|
| A. Compose-hosted stage | A small Expo native module hosts a Compose "stage" (orb scene + glass controls) that contains both the backdrop and glass. RN keeps the transcript, composer logic and state | The orb and glass surfaces are rendered twice (Compose and RN), the orb must be redrawn in Compose, and touch and state bridging is needed | Real AndroidLiquidGlass effect on the stage. The RN transcript is not refracted |
| B. Capture RN into Compose | The native view snapshots RN content to a bitmap and feeds it to the library as backdrop | Per-frame snapshots are heavy and brittle on low-end Android | Real library effect, but slow |
| C. Port the shader approach | Use RN-side blur plus an AGSL refraction view, taking the *idea* from the library | Not the library's code | An approximation only, to be labelled as such |

Recommendation: **A**, limited to the surfaces that sit on the orb stage (theme sheet and floating controls), with an RN fallback (opaque or translucent tinted surfaces) elsewhere and on iOS or Android below 13. This keeps React Native in charge of the conversation, as required.

### Build requirements (for A)

- A **development build** is mandatory (Expo Go cannot load custom Kotlin). `android/` would be generated by prebuild (CNG) and must not be hand-edited.
- Toolchain present: Android Studio JBR (JDK 17+; the shell `java` is 1.8 and must not be used), NDK 27 and 28, CMake 3.22.1, SDK platforms 36.1 and 37.0. A cold RN 0.88 build, Gradle downloads and the Compose compiler setup will take a long time and several GB.
- Added dependencies: a local Expo module (`modules/liquid-glass`) and the `io.github.kyant0:backdrop` Gradle artifact. These are justified only by the demonstrated blocker above.

## 4. JS-side design (independent of the native decision)

Reuse and extend, no rewrite:

- `src/theme/` - `colors.ts` (dedicated light and dark palettes), `ThemeProvider.tsx` (one provider; preference `system | light | dark`, persisted), `useTheme.ts`.
- `src/orb/orbPalettes.ts` - eight palettes (Aurora, Ocean, Sunset, Emerald, Rose, Glacier, Solar, Amethyst), each a layered gradient set. `useOrbTheme` is persisted and independent of voice settings (a separate `voiceIdentity` slot reserved, with no behaviour).
- `VoiceOrb.tsx` takes a palette and morphs by cross-blending layer colours with an Animated value, never remounting, so playback, recording and conversation are untouched.
- `src/components/glass/` - `GlassSurface`, `GlassButton`, `GlassIconButton`, `GlassBottomSheet`, `GlassComposer`, `GlassControlGroup`, `GlassThemeSelector`, all behind one abstraction with the native renderer plugged in where available.
- Opening and swipe transition: reuse `AppShell` progress, add background blur and the rising tinted glass sheet, with back-button collapse, accessibility "activate" action, and reduced-motion handling.
- Persistence: one small JSON file via the existing local storage approach (same pattern as the consent file). No backend.
- Every existing screen, modal and dialog is moved to theme tokens. The existing contrast tests are extended to run for both modes.
